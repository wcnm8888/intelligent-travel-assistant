# 轻量 Web UI 设计规格

## 文档状态

本文件定义 MVP 的产品交互方向和 B-000 工程诊断页契约，不是最终视觉稿。B-000 只实现健康诊断页；旅行规划工作台属于后续用户价值任务，届时需要在任务卡中细化并执行相应 UI 验收。

## 设计目标

- 让用户在一个清晰流程中输入需求、查看计划、理解冲突并发起局部修改；
- 让数据来源、更新时间、费用可信状态和未知项与行程内容同等可见；
- 在外部服务失败时保留可用结果，明确说明影响和恢复动作；
- 在跨日、跨城或住宿变更前展示影响范围并取得确认；
- 桌面优先，同时保证窄屏下可读和可操作；
- 不依赖复杂地图、图片或装饰性动画完成核心任务。

## 核心用户故事

```text
作为自由行用户，
我希望输入旅行约束并得到可校验的逐日计划，
以便在自行预订前做出有依据的选择。
```

```text
作为预算敏感的用户，
我希望看到费用来源、可信状态和未知项，
以便不把不完整合计误认为真实总价。
```

```text
作为需要调整计划的用户，
我希望只修改某一天或某个景点，
以便保留其他已经确认的安排。
```

## MVP 信息架构

第一版使用单一旅行规划工作台，不建立复杂多页面导航：

```text
顶部：项目状态 / 当前计划版本 / 数据更新时间
├─ 需求输入区
├─ 处理进度与失败提示
├─ 计划摘要
│  ├─ 日期与城市
│  ├─ 已知预算 / 未知项
│  └─ 关键天气与冲突
├─ 逐日行程
│  ├─ 活动与 POI
│  ├─ 交通段与预计耗时
│  ├─ 费用项
│  └─ 当日来源与警告
├─ 来源与不确定性
├─ 冲突与待确认事项
└─ 局部重规划操作
```

复杂地图、相册、PDF 预览、预订入口和账户设置不出现。

## 主流程

### 创建计划

1. 用户填写目的地、日期、人数和总预算；
2. 用户补充兴趣、节奏、交通和住宿要求；
3. 前端执行格式校验，提交到后端；
4. 系统分阶段展示“规范化需求、获取数据、生成计划、代码校验”；
5. 缺少必要硬约束时，界面回到对应字段并说明原因；
6. 成功时展示计划；部分数据缺失时展示 `partial` 结果和恢复动作；
7. 用户检查预算、来源、警告和冲突，再决定是否调整。

### 局部重规划

1. 用户在某一天或某个活动上选择替换、删除、调整时间或补充要求；
2. 系统显示预计影响范围；
3. 只影响当天内部时，可直接执行并显示变更摘要；
4. 影响住宿城市、跨城交通或相邻日期时，显示受影响日期和原因；
5. 用户确认后才生成新计划版本；取消则保留原版本；
6. 新旧版本显示变化项，不把未受影响日期伪装为重新验证。

### 外部服务失败

1. 保留已经成功获取和验证的数据；
2. 在对应模块显示 provider、错误类别和影响，而不是全页空白；
3. 可重试错误提供明确的重试操作；
4. 配置缺失或鉴权失败指向本地配置说明，不反复自动请求；
5. 不能安全生成计划时停止并说明还需要什么。

## 输入契约方向

| 输入 | 控件方向 | 必要性 | 主要校验 |
| --- | --- | --- | --- |
| 目的地 | 城市/地点输入与候选确认 | 必填 | 不能只保留歧义文本，需确认规范地点 |
| 开始与结束日期 | 日期范围 | 必填 | 开始不晚于结束，跨度在产品允许范围内 |
| 同行人数 | 正整数输入 | 必填 | 大于 0，面向小型同行群体 |
| 总预算 | 金额与币种 | 必填 | 金额大于 0，MVP 默认 CNY |
| 兴趣偏好 | 多选和补充文本 | 选填 | 区分偏好与必须条件 |
| 行程节奏 | 单选 | 选填 | 舒缓、均衡、紧凑等受控值 |
| 城际/市内交通要求 | 受控选项和补充文本 | 选填 | 保留禁用方式和硬约束 |
| 住宿要求 | 区域、设施、预算或用户价格 | 选填 | 不暗示实时库存或可订 |
| 其他限制 | 文本或结构化选项 | 选填 | 长度限制，不作为系统指令执行 |

真实 API 和领域 Schema 在对应实现任务中确定。前端类型不能代替服务端和领域校验。

## 输出与组件契约方向

### 计划摘要

必须展示：

- 目的地、日期范围、人数和计划版本；
- 当前状态：`ready`、`partial` 或 `conflict`；
- 已知费用合计、预算、未知费用项数量；
- 关键天气风险、主要冲突和待确认事项；
- 最近数据更新时间。

存在未知费用时，不显示“预算充足”这种完整结论，只显示已知部分与预算的关系。

### 逐日计划

每天展示：

- 当地日期、城市和住宿区域/地点；
- 按时间排序的活动、POI、预计停留和费用；
- 活动之间的交通方式、预计距离和时间；
- 天气提示、警告、冲突和未验证项；
- 当天可执行的局部修改入口。

POI 卡片不得显示“可订”“最低价”或“营业中”，除非未来接入能证明这些字段的权威数据源。

### 来源与不确定性

来源可以按字段或记录关联，界面至少可查看：

- provider 名称；
- 获取时间；
- 有效期或“有效期未知”；
- 费用可信状态；
- 数据缺失、过期、估算假设或冲突警告。

不得只在页脚放一个笼统“数据来自第三方”的说明。

### 影响确认对话框

必须包含：

- 用户请求的修改；
- 受影响日期、城市、住宿和跨城交通；
- 将保留与将重新计算的范围；
- 可见的确认和取消操作；
- 取消后原计划不变的说明。

默认焦点和按钮文案不能诱导用户无条件确认。

## 页面状态

| 状态 | 用户看到 | 可用操作 |
| --- | --- | --- |
| `initial` | 空白需求表单和必要说明 | 填写 |
| `editing` | 已输入内容和字段校验 | 修改、提交 |
| `submitting` | 请求正在提交 | 取消重复提交 |
| `normalizing` | 正在检查和规范需求 | 等待 |
| `needs_input` | 缺失字段和原因 | 补充后继续 |
| `collecting` | 正在获取地点、路线和天气，显示分项进度 | 可取消当前流程 |
| `planning` | 正在生成结构化计划 | 等待 |
| `validating` | 正在执行代码校验 | 等待 |
| `ready` | 完整计划和校验摘要 | 查看、局部修改 |
| `partial` | 可用计划、缺失数据和影响 | 查看、补充、重试 |
| `conflict` | 不能自动解决的冲突 | 调整约束或确认影响 |
| `awaiting_confirmation` | 影响范围与确认内容 | 确认或取消 |
| `replanning` | 正在生成新版本 | 等待，保留旧版本 |
| `error` | 错误类别、影响和恢复动作 | 重试、返回编辑或查看部分结果 |

加载状态不能只显示无限转圈；应说明当前阶段。可重试与不可重试错误必须有不同动作。

## B-000 健康诊断页

B-000 只交付工程诊断页，用来证明前端和后端本地闭环，不作为正式产品视觉基线。

| 状态 | 展示 | 行为 |
| --- | --- | --- |
| `loading` | 正在检查本地 API | 禁用重复检查 |
| `success` | 前端可用、后端已连接、服务名 | 可再次检查 |
| `error` | 后端不可用的可理解说明 | 显示重试按钮 |
| `retry` | 重新发起健康请求 | 回到 loading |
| `disabled` | 请求进行中 | 按钮不可用但仍可读 |

诊断页不创建假旅行数据、景点卡片、地图或规划输入表单。

## 错误语义

- 字段错误靠近字段展示，并在提交摘要中可定位；
- provider 失败显示服务类别和影响，不显示 Key、Token、原始堆栈或完整响应；
- `partial` 不是成功的同义词，必须持续显示缺失项；
- `unknown` 费用使用“未知”文案和空金额，不显示 `¥0`；
- 数据过期显示获取时间和“可能已变化”；
- 模型输出不合法归类为系统规划失败，不让用户看到原始模型内容；
- 跨日或跨城修改使用 `confirmation_required`，不是普通错误。

## 响应式与可访问性

- 核心信息在常见桌面宽度和窄屏下不发生水平溢出；
- 窄屏按“摘要、冲突、逐日计划、来源”顺序纵向排列；
- 状态不能只依赖颜色，配合文本和图标含义；
- 表单控件有可见标签、错误关联和键盘焦点；
- 对话框可用键盘进入和退出，取消操作始终可见；
- 时间、金额和日期使用中文用户熟悉的格式，同时保留机器字段语义；
- 动画不作为必要反馈，尊重减少动态效果偏好。

## 架构边界

- UI 不计算最终预算、路线冲突或重规划影响范围；
- UI 不直接访问 DeepSeek、高德和和风天气；
- UI 不保存第三方 Key；
- 服务端返回计划 view model、来源、错误和允许操作；
- 前端可以进行即时格式提示，但服务端和领域层仍需完整校验；
- 正式视觉系统、地图组件和多页面导航需要独立批准任务。

## 验收方向

- 用户能完成输入、提交、查看计划和局部修改的主流程；
- `loading`、`ready`、`partial`、`conflict`、`error` 和 `awaiting_confirmation` 可独立复现；
- 未知费用、过期数据和 provider 失败不会被隐藏；
- 当天修改与跨日/跨城修改表现出不同确认行为；
- 计划内容、来源和警告在窄屏仍可读；
- 无登录、预订、支付、实时库存、复杂地图、图片或 PDF 入口。

具体可执行测试和视觉检查在后续任务卡与 `testing-strategy.md` 中定义。

## 非目标

- B-000 中实现旅行规划工作台；
- 品牌视觉、插画、图片库或复杂动画；
- 实时地图绘制和路线拖拽；
- 酒店、票务和支付交易流程；
- 登录、云同步和多人协作；
- PDF、图片海报或公开分享页。
